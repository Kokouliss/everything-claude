# Building lean Elementor sites from Figma, XD or references

This guide is for the plugin's own agent when it builds a new Elementor 4.x site from a Figma file, an Adobe XD file or reference screenshots, through Novamira. Every page it hands over must pass the same gate the plugin applies to measured sites (`references/sites-in-the-wild.md`, "Rules the plugin adopts"): mobile Lighthouse median ≥ 95 over three serial runs, LCP ≤ 2.0 s, CLS ≤ 0.05, TBT < 300 ms, page weight ≤ 1 MB, ≤ 50 requests, zero render-blocking resources, LCP element a text node or an `<img>` with `fetchpriority="high"` and no `loading="lazy"`, third-party JS ≤ 150 KB and ≤ 300 ms blocking before interaction, hero image ≤ 100 KB AVIF/WebP, ≤ 2 font families in ≤ 4 woff2 files, zero icon-font files, no animation above the fold, HTML under 300 KB and 1,500 DOM nodes. A score that rounds to 100 needs tighter per-metric values derived from the Lighthouse scoring curve: LCP ≈ 1.55 s, TBT ≈ 66 ms, CLS ≈ 0.04, FCP ≈ 1.1 s, Speed Index ≈ 2.0 s ([scoring](https://developer.chrome.com/docs/lighthouse/performance/performance-scoring), [Lighthouse 13 keeps the weights](https://developer.chrome.com/blog/lighthouse-13-0)). Facts below come from the plugin's reviewed research corpus (October 2026); claims from the Theme Builder/popup study were not critic-reviewed and are marked "(unreviewed)". Where a detail was cut from the corpus and not re-verified it says "verify".

Pre-conditions (menu paths in §7, site setup): Elementor Core ≥ 4.3.4 with Pro on the matching 4.3.x, CSS Print Method = External File, Atomic Editor on, and `novamira/elementor-check-setup` reporting `atomic.runtime_available`, `global_classes_available` and `variables_available` true before an atomic tree is written — none of the agency's sites checked had `e_atomic_elements` on ([4.0 announcement](https://elementor.com/blog/editor-40-atomic-forms-pro-interactions/), [V4 FAQ](https://elementor.com/products/website-builder/v4-faq/), [readme changelog](https://raw.githubusercontent.com/elementor/elementor/main/readme.txt)).

## 1. From design file to tokens

The token sheet is written once per site, before the first page, and becomes an Elementor Design System export that seeds every later site.

### Extracting

| Source | What to read | How | Confidence |
|---|---|---|---|
| Figma (any plan) | Fills, strokes, `style.fontFamily/fontSize/fontWeight/lineHeightPx/letterSpacing`, `cornerRadius`, `itemSpacing`, `padding*`; published colour/text styles | REST with a personal access token: `GET /v1/files/{key}?depth=2` for the page/frame list, `GET /v1/files/{key}/nodes?ids=…`, `GET /v1/files/{key}/styles`; rasters via `GET /v1/images/{key}?ids=…&format=png&scale=2` (`scale` 0.01–4, `format` jpg/png/svg/pdf) ([REST access tiers](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/)) | high |
| Figma Variables | Bound variables (colour/number/string modes) | `GET /v1/files/{key}/variables/local` is **Enterprise-only** (403 elsewhere); on other plans read the resolved values from the node fills/styles instead ([Variables API](https://developers.figma.com/docs/rest-api/variables/)) | high |
| Figma MCP | `get_variable_defs`, `get_design_context` on a frame | Only with a Dev/Full seat; Starter/View seats get 20 calls per month. The connector in this environment is **not authorised**; the owner must authorise it in claude.ai connector settings first. Fall back to REST. | high |
| Adobe XD | Artboard sizes, colours, text styles | `unzip -o design.xd -d xd/`; parse `xd/resources/graphics/graphicsContent.ags` and `xd/artwork/*/graphics/graphicsContent.ags` with `python3 -I` for `fill.color.value` (r,g,b → hex), `style.font.family/style/size`, `style.textAttributes.lineHeight/letterSpacing`, artboard `width/height`. The JSON schema is undocumented and the npm parsers are unmaintained; export rasters and SVGs from XD itself (Export → Batch, 2× PNG + SVG). XD is in maintenance mode with no official migration ([xd-file](https://cdn.jsdelivr.net/npm/xd-file/README.md), [xd2svg](https://cdn.jsdelivr.net/npm/xd2svg@2.0.1/README.md)) | **low** until one real agency `.xd` is parsed |
| Screenshots | Palette, type scale, spacing rhythm, components | Angie: paste the screenshot with "Create reusable classes and variables based on the attached image"; it writes colour and typography variables and primary classes into the Design System panel. Then prune ([Angie help](https://elementor.com/help/use-angie-ai-to-create-variables-and-classes-based-on-existing-pages/), [Elementor MCP](https://elementor.com/blog/elementor-mcp-launch/)). Manual alternative: the `image-to-code` skill's extraction rules (§21–25: text, typography, spacing, button, colour) produce the same sheet without credits. | medium |
| Live reference site | Computed tokens | `extract-design-system <url>` skill → `.extract-design-system/normalized.json` | medium |

Shadows: `cornerRadius` is confirmed in the Figma node JSON; shadow and blur fields were not in the corpus — read them from the node and verify the field names before relying on them.

### Pruning to the budget

AI and designer palettes over-produce. Before anything is created in Elementor: ≤ 8 colours with semantic names (`color-brand-primary`, `color-surface`, `color-text`), **2 font families** (one heading, one body), **1 size scale**. Delete one-off classes in the Class Manager. Every heading/button on the first page must end up with a global class and no local colour/font override.

### Where each token lands in Elementor 4.x

| Token | Lands in | Notes |
|---|---|---|
| Colours | Design System → Variables → Color | V4 Variables are native to atomic elements only; v3 Pro widgets (Nav Menu, Form, Loop) still read kit Global Colors — create both when a v3 widget is used ([V4 FAQ](https://elementor.com/products/website-builder/v4-faq/)) |
| Font families | Variables → Font | Typography variables cover **family only**; size/weight/line-height go into classes |
| Size scale, spacing, radii | Variables → Size (clamp() strings accepted — verify on 4.3.x) + classes | |
| Components (button, card, section widths) | Global Classes: `btn-primary`, `btn-ghost`, `card`, `section-boxed`, `section-full`, `heading-display` | Classes are stored on the active kit as post meta `_elementor_global_classes` (`items` + `order`); `GET /wp-json/elementor/v1/global-classes` lists them |
| Tag baselines | Design System → Defaults: h1–h6, p, a, button, **div padding 0** | Div Block and Flexbox both carry a 10 px base padding and `min-width:30px`; the `div` default of 0 removes it site-wide |
| v3 kit (for Pro v3 widgets) | Site Settings → Global Fonts/Colors via `novamira/elementor-create-v3-typography` / `elementor-create-v3-color`; read back with `elementor-list-v3-styles` | Verify argument names with `mcp-adapter-get-ability-info` before the first call |
| Global classes through Novamira | `novamira/elementor-create-global-class` takes the same flat `{css-prop: value}` styles map as element styles (§5) | |

Export the finished set: Design System panel → ⋯ → Export (ZIP of variables + classes; import is all-or-nothing, name conflicts ask override/keep — "override" silently restyles existing pages). Alternative: Elementor → Editor → Tools → Website Templates → Export with only Settings & configurations → Classes + Variables. Keep `agency-base-design-system.zip` in the plugin and import it on every new site before the first page ([export/import help](https://elementor.com/help/how-to-export-and-import-variables-and-classes/), [kit import CLI](https://developers.elementor.com/docs/cli/kit-import)).

### Design fonts

- Two families, 2–3 weights each. Variable families (Inter, Open Sans, Noto Serif Display, EB Garamond) serve one file per subset whatever the weight, so extra weights cost 0 bytes; static families (Poppins, Roboto) cost a file per weight. Measured: Inter latin 47.3 KB + greek 18.6 KB; Open Sans 42.0 + 17.3; Roboto 29.6 + 39.1; EB Garamond 23.2 + 10.5; Poppins has **no Greek** — pick a family with a `greek` subset first.
- Budget: ≤ 4 same-origin woff2 files, ~100 KB (rules.md allows 150 KB), `font-display: swap`, only the LCP heading font preloaded.
- Subset **before** upload (Pro Custom Fonts has no unicode-range field): Latin + Greek U+0370–03FF, plus Greek Extended U+1F00–1FFF only for polytonic text — `pyftsubset Font.ttf --flavor=woff2 --layout-features='*' --unicodes='U+0000-00FF,U+0131,U+0152-0153,U+02BB-02BC,U+02C6,U+02DA,U+02DC,U+2000-206F,U+20AC,U+2122,U+2191,U+2193,U+2212,U+2215,U+FEFF,U+FFFD,U+0370-03FF'` (Modak .woff 271 KB → 42.7 KB; InterTight 105 KB → 36.9 KB). Without a toolchain: google-webfonts-helper, charsets latin + greek, woff2 only (Inter regular 29.7 KB). Pro also takes variable fonts ([Custom Fonts](https://elementor.com/help/custom-fonts-pro/), [variable fonts](https://elementor.com/help/use-variable-fonts/)).
- Upload: Elementor → Editor → Custom Elements → Add New Font → Add Static Font per weight, woff2 only; child theme `add_filter('elementor_pro/custom_fonts/font_display', fn() => 'swap', 10, 3)`, re-save each font, Regenerate CSS ([font-display](https://developer.chrome.com/docs/lighthouse/performance/font-display)). Then Settings → Advanced: Google Fonts Load = Swap and **Google Fonts = Disable**; Settings → General: Disable Default Fonts/Colors ([disable Google Fonts](https://elementor.com/help/disable-google-fonts/), [defaults](https://elementor.com/help/disable-elementors-default-fonts-and-colors/)).
- Google families only: Settings → Performance → Load Google Fonts Locally = Enable keeps Google's per-subset `@font-face`; Elementor adds `&subset=greek` only when the WP locale is exactly `el`; one tool localises fonts, never Elementor **and** the cache plugin ([google-font.php](https://raw.githubusercontent.com/elementor/elementor/main/core/files/fonts/google-font.php)).
- V4 typography uses the same enqueue path as v3; keep typography in Variables/Classes, never per element (medium) ([Style tab typography](https://elementor.com/help/style-tab-typography/)).
- Icons: never an icon font. Inline Font Icons (SVG) on, Font Awesome 4 Support off, icons as `e-svg`/uploaded SVG; Fontello/IcoMoon sets stay icon fonts.

## 2. Component → widget mapping

Atomic elements registered in `modules/atomic-widgets/module.php`: Div_Block, Flexbox, Grid, Heading, Paragraph, Button, Image, Svg, Divider, List, Accordion, Tabs, Youtube, Self_Hosted_Video, Background_Video, Google_Maps, Atomic_Form (Pro). Every Elementor page with Pro ships ~130 KB gzip of Elementor JS before any widget (Pro `elements-handlers.min.js` ~70 KB gzip is monolithic); only Swiper (~38 KB), lightbox (~27 KB), nested-tabs (~13 KB), counter (~7.5 KB) and video (~8 KB) are conditional ([asset loading](https://developers.elementor.com/experiment-optimized-asset-loading/)). ## 3. Structure rules

**Containers and depth.** Containers only (never sections/columns). Section = one `e-div-block` for the full-bleed band containing at most one `e-flexbox`/`e-grid` for the boxed content (`section-boxed` class). Cards are `e-grid` children. Depth ≤ 4 counted from `content[]`. Flexbox only where direction/gap is needed; Grid for repeated cards. Both Div Block and Flexbox carry 10 px base padding and `min-width:30px`, hence the Defaults `div` padding 0. No container whose only job is padding — merge it into the parent. Lint the tree for depth and single-child wrappers. Atomic markup renders without wrapper layers; v3 Optimized Markup (`e_optimized_markup`) removes `.elementor-widget-container` and is default-inactive on existing installs — custom CSS targeting removed wrappers silently stops applying ([Optimized DOM](https://developer.chrome.com/docs/lighthouse/performance/dom-size), [V4 FAQ](https://elementor.com/products/website-builder/v4-faq/)). Mixing a v3 `container` with atomic `e-*` children in one subtree produces a broken hybrid; pick one world per subtree (Novamira refuses it).

**DOM/HTML budget in practice.** rules.md warns at 300 KB raw HTML or 1,500 nodes and flags at 600 KB / 2,500; the build target is body < 800 nodes, max children < 60. DOM size alone did not decide the score on the audited sites (2,024 nodes scores 86; 703 nodes scores 27), so it is a guard rail, not the lever — the lever is what the nodes carry (animations, images, scripts). Measure with the Lighthouse `dom-size-insight` audit.

**Theme Builder templates and their per-page cost (unreviewed).** Each Elementor document on a page adds one render-blocking `post-N.css`: page + kit + header + footer = 4 on a brochure page, plus one per rendered popup and per Template-widget insert; loop items inline `<style id="loop-N">`. Target ≤ 4. Header tax measured: smartmenus 6–7 KB with Nav Menu, `jquery.sticky` 1 KB, mega-menu/menu-cart CSS 2–3 KB each render-blocking, Menu Cart's `?wc-ajax=get_refreshed_fragments` XHR 1.5–5 s. Footers measured 35–100 KB raw HTML: text, links, SVG icons only — no Form, map or feed. Header and footer as single containers. Rules:

- Header: no entrance animation on any element; logo with exact width/height; prefer the Menu widget dropdown/Off-Canvas for mobile over a popup.
- One header/footer per language (Polylang): register `general/pll_language_<slug>` sub-conditions from a site mu-plugin (`elementor/theme/register_conditions`, class extending `Condition_Base` whose `check()` compares `pll_current_language()`) — the pattern from the `kallyas-to-elementor` skill §5; translated templates intentionally have zero conditions when Connect Polylang swaps them (unreviewed).
- Pro caches resolved conditions in option `elementor_pro_theme_builder_conditions`; editing `_elementor_conditions` outside the editor has no effect until it is rebuilt (unreviewed) ([theme conditions](https://developers.elementor.com/docs/theme-conditions/)).
- Landing/booking pages: Page Layout = Elementor Canvas (`_wp_page_template = elementor_canvas`) to drop header, footer and popups; checkout: a minimal header (logo + phone) with Include → Singular → Checkout and an Exclude on the main header, footer and every popup (unreviewed) ([conditions help](https://elementor.com/help/conditions/)).
- Single/archive templates: one loop-item template per content type; Loop Grid pagination Numbers or Load on Click, not Infinite Scroll (unreviewed).
- Element Cache: do not enable on sites with bookings, WooCommerce, JetSmartFilters or Polylang dynamic strings; it is not a scoring lever and breaks dynamic widgets.

**Popups (unreviewed).** Triggers live in `_elementor_popup_display_settings` (`{triggers, timing}`; `triggers: []` = manual-only). Conditions: Include → Singular → Pages → only the pages that open it, Exclude checkout/booking; an opener on a page outside the conditions silently does nothing. Scroll or time triggers only. Unused-CSS removal does not see hidden popups — safelist `.elementor-location-popup .elementor-popup-modal .dialog-widget-content .elementor-sticky--effects .e-n-menu-content .elementor-menu-cart__container .elementor-off-canvas` ([FlyingPress RUCSS](https://docs.flyingpress.com/en/articles/11406594-remove-unused-css)).

**Responsive strategy: one DOM.** "Hide On Mobile"/Display: None is CSS-only (`display:none` at ≤ 767 px in `frontend.min.css` 4.3.5): eager and `fetchpriority=high` images, autoplay `<video src>` and inline scripts in the hidden tree still download on phones, and a hidden desktop hero takes the single high-priority slot ([show/hide help](https://elementor.com/help/show-or-hide-columns-per-device/)). So: one container per section, device differences through responsive Style values (v4 `styles` variants with `meta.breakpoint`; v3 `<key>_mobile`/`_tablet` suffixes), never two trees. Device-specific hero images without a cache vary: `<picture><source media="(max-width:767px)" srcset="hero-mobile-828.webp"><img src="hero-1600.webp" width height fetchpriority="high" loading="eager">` in an HTML widget (Optimized Image Loading keeps attributes you write yourself). Never `wp_is_mobile()`/Dynamic Visibility device rules: the first visitor's device poisons the shared page cache. V4 Interactions are JavaScript-driven and apply to all devices; they live in each element's `interactions` array, which is what the lint checks ([Interactions](https://developers.elementor.com/docs/data-structure/atomic-elements)).

## 4. Images, fonts, scripts budget during build

**Images — numbers.** Hero ≤ 100 KB AVIF/WebP sized for 390–430 px phones; no first-viewport image > 200 KB; no page image > 300 KB; no PNG > 100 KB for photos or posters; nothing served at `-scaled`/original to mobile; all images from the site origin (or its CDN); no base64 image > 20 KB; any Media resource > 500 KB is a finding (rules.md 4–5). Chosen `srcset` candidate ≤ 2× rendered width at 390 px.

**Export pipeline.**
1. Export from Figma at 2× (`scale=2`) or from XD (Batch 2×); logos/icons as SVG.
2. Generate outside the design tool with sharp/cwebp/avifenc: hero 1920 / 1280 / 768 px wide in AVIF (q ≈ 50–60) with WebP fallback; cards at 2× their box width. WordPress 6.5+ generates AVIF sub-sizes if Imagick/GD supports it (Tools → Site Health → Info → Media Handling); quality via `add_filter('wp_editor_set_quality', fn($q,$m) => 'image/avif'===$m ? 75 : $q, 10, 2)`. Largest edge ≤ 2560 px or WordPress makes a `-scaled` copy ([image delivery](https://developer.chrome.com/docs/performance/insights/image-delivery), [responsive images](https://developer.chrome.com/docs/lighthouse/performance/uses-responsive-images)).
3. Register sizes in the child theme and expose them: `add_image_size('hero-mobile', 780, 0); add_image_size('card-2x', 800, 0); add_filter('image_size_names_choose', fn($s) => $s + ['hero-mobile' => 'Hero mobile', 'card-2x' => 'Card 2x']);`.
4. In every `e-image` set `settings.image.value.size` to a registered size, never `full`. Atomic `e-image` emits `id, src, width, height, srcset, alt` and **no `sizes`**, so phones download the ~100vw candidate unless the size is pinned ([atomic-image.html.twig](https://raw.githubusercontent.com/elementor/elementor/main/modules/atomic-widgets/elements/atomic-image/atomic-image.html.twig), [WP 6.7 auto sizes](https://make.wordpress.org/core/2024/10/18/auto-sizes-for-lazy-loaded-images-in-wordpress-6-7/)). In v3 Image widgets never choose Image Resolution "Custom": it emits a hand-built `<img>` with hard-coded `loading="lazy"` and no width/height/srcset ([image-size.php](https://raw.githubusercontent.com/elementor/elementor/main/includes/controls/groups/image-size.php)).
5. One converter per site (LiteSpeed Image Optimization with AVIF/WebP on LiteSpeed hosts, else Converter for Media or Imagify); never two.

**Hero image rules.** The hero is an `<img>` (`e-image`), never a container background: Lazy Load Background Images (default Enable) hides every CSS background but the first with `background-image:none !important` until JS runs ([image loading help](https://elementor.com/help/image-loading-optimization/)). Optimized Image Loading (default Enable) replaces WordPress core logic: the first three dimensioned `<img>` stay eager, the first one ≥ 50,000 px² gets `fetchpriority="high"`, the rest become lazy, attributes you set yourself are kept, images without width/height are ignored. So the hero `<img>` is the first large dimensioned image in the HTML and the header logo has exact small dimensions. **Exactly one image lazy-loader: Elementor** — LiteSpeed Lazy Load Images OFF, FlyingPress lazy load off, Perfmatters Lazy Loading → Images off; stacking produced CLS 0 → 0.107 on staging ([module.php](https://raw.githubusercontent.com/elementor/elementor/main/modules/image-loading-optimization/module.php), [fetch priority](https://perfmatters.io/docs/fetch-priority/)). Verify in view-source: hero `<img>` has `fetchpriority="high"`, `width`/`height`, `srcset`, no `loading="lazy"`, no `data-src`.

**Video.** Poster for every `<video>` (optimised WebP/AVIF frame); `preload="none"` on every non-hero video; no autoplay above the fold on mobile; muted desktop loop ≤ 1 MB at 720p via the `<source media>` pattern (§2). Any Media resource > 500 KB in the network log is a finding.

**Fonts.** The §1 numbers: 2 families, ≤ 4 files, ~100 KB, swap, LCP heading font preloaded, zero requests to `fonts.googleapis.com`/`gstatic`/`typekit`, zero `.woff`/`.ttf`. Verify: DevTools Network font filter, and a Greek paragraph renders in the brand font (check ά, ώ, ς).

**Icon fonts: zero files.** `eicons`, `fa-*`, `elementskit*.woff`, MDI, `simple-line-icons` in the network log are findings.

**Scripts.** The ~130 KB gzip Elementor+Pro floor is fixed; everything else is budget: third-party ≤ 150 KB and ≤ 300 ms blocking before interaction; **one GTM container**, one gtag bundle; pixel, ads, chat, booking and Hotjar inside GTM or delayed to interaction/consent (Perfmatters "Delay only specified": `/gtm.js`, `fbevents.js`, `connect.facebook.net`, `googleads`, `doubleclick`; FlyingPress "Load third-party scripts on interaction"; LiteSpeed Delay for third parties) — fast sites show 0 KB third-party in the lab, slow ones 470–1,420 KB ([case](https://adventuresinwordpressing.substack.com/p/elementor-sites-arent-slow-how-to)). The CMP loads directly, excluded from delay. No `<script>` in HTML widgets; scripts live in the child theme — the one exception is a desktop-only hero facade loader (`<script type="module">` gated on `matchMedia('(min-width:1025px)')`, excluded from Delay-JS) when the brief forces a heavy desktop hero; prefer the zero-JS `<source media>` pattern. Dequeue before delay: no Swiper consumer, no Counter, global lightbox off, no add-on pack unless a widget is needed. v4 Interactions (`motion.min.js` 128 KB raw) load only on pages that use one; none on the first screen, ≤ 2 per page. Cache-plugin CSS: exclude `/wp-content/plugins/elementor/assets/css/` from async/RUCSS, LiteSpeed "CSS Per URL" on, CSS Combine off, Rocket Loader off ([LiteSpeed page optimisation](https://docs.litespeedtech.com/lscache/lscwp/pageopt/), [FlyingPress lazy render](https://docs.flyingpress.com/en/articles/11406903-lazy-render-elements)).

## 5. Building programmatically

**The data.** `_elementor_data` holds the JSON array of top-level elements; template/export files wrap it as `{title, type (page|header|footer|error-404|popup|post…), version: "0.4", page_settings: []|{}, content: […]}`. Writing the meta directly needs `wp_slash` before `update_post_meta` or escaped characters corrupt; through Novamira this is handled ([atomic elements](https://developers.elementor.com/docs/data-structure/atomic-elements), [atomic widgets](https://developers.elementor.com/docs/data-structure/atomic-widgets)).

Element shapes (confirmed on developers.elementor.com):

- v3: `{id (7–8 hex), elType: "container"|"widget", widgetType, isInner, settings: []|{}, elements: []}`. v3 value rules (from the Novamira schema): switchers `"rv"` on / `""` off; typography needs `typography_typography: "custom"` first; dimensions `{unit, top, right, bottom, left, isLinked}`; sliders `{size, unit}`; colours `#RRGGBB`; responsive overrides via `<key>_tablet` / `<key>_mobile`.
- Atomic layout: `{id, version: "0.0", elType: "e-div-block"|"e-flexbox"|"e-grid", isInner, settings, editor_settings, interactions: [], styles: []|{}, elements}`. Atomic containers have only structural settings (`tag`, `link`, `classes`, `attributes`); all layout, spacing, background and typography go in `styles`.
- Atomic widget: `elType: "widget"`, `widgetType: "e-heading"|"e-paragraph"|"e-button"|"e-image"|…`, typed settings `{"$$type": …, "value": …}`: `tag` as `string`, text as `html-v3` (`{content: {$$type: "string", value}, children: []}`), `link` as `link` with `destination` (a `query` for internal posts, confirmed; `url` type exists in the prop types — verify the envelope with `elementor-get-schema`), `isTargetBlank`, `tag`. Image: `image` → `{src: {$$type: "image-src", value: {id: {$$type: "image-attachment-id", value}, url}}, size: {$$type: "string", value: "<registered size>"}}` (keys from `image-prop-type.php`; `size` affects file choice only, dimensions come from styles).
- Per-element `styles` (Novamira accepts two shapes): flat `{css-prop: value}` synthesised into one base variant under class `s-<id>`, or verbose `{"<style_id>": {id, type: "class", label: "local", variants: [{meta: {breakpoint, state}, props: {...}}]}}` for breakpoints/states (hover etc. only via `variants[].meta.state`).

**What `novamira/elementor-set-content` needs** (schema read from the dev site 2026-10-21): `post_id`, `content` (array of element objects; `[]` wipes the document), optional `template_type` (`"wp-page"`, `"header"`, `"footer"`, `"single-post"`, `"loop-item"`…; omit to keep the existing type). Node keys are exactly `id`, `elType` (alias `element_type`), `widgetType` (alias `widget_type`), `settings`, `elements`, `styles`; misspellings such as `element_id`, `children`, `style`, `is_inner`, `editorSettings` are refused by name. Omit `id` for a 7-hex auto id or pass a kebab-case slug (`hero`, `hero-cta`): it becomes the rendered `data-id` and the `s-<id>` class. Validation is server-side — unknown control ids or enum values abort the write and return the compact schema inline; `elementor-get-schema` (`widget_types: ["__container__"]` for containers) and `elementor-get-style-schema` are optional discovery. Atomic scalars auto-wrap into `{$$type, value}` in `settings` and `styles.props`; compound values (image, background, border) need their nested shape. Single-line text controls take plain text, wysiwyg inline tags only. The write is verified by read-back (`elements_written`); `not_persisted` lists dropped keys, `warnings` text Elementor will filter. `elementor-add-element` accepts the same subtree in tree mode (`post_id`, `tree`, `parent_id`, `position`; `elType` on every node). Atomic `e-*` nodes need `atomic.runtime_available: true`; otherwise build `container` + v3 widgets (the dev site checked today accepts only `widget`/`container`).

**Sequence per page.** Generate the tree from the section spec → local lint (no non-empty `interactions` or `_animation`/`motion_fx` in the first section, ≤ 2 interactions per page, depth ≤ 4, only whitelisted `widgetType`s, every `e-image` with a registered `size`, no `<script>` in `html`) → `elementor-set-content` to a **draft** post with `template_type: "wp-page"` → `novamira/elementor-clear-document-cache` (purges that document's CSS; the ability also fires `clean_post_cache` so optimisers purge) → screenshot at 390 px → Lighthouse. `elementor-get-content` must return the same top-level ids; the editor must open without a data-migration notice.

**Templates and kits.** Headers/footers/popups/loop items are written to `elementor_library` posts with the matching `template_type`, then conditions are set in the editor (Publish Settings → Conditions) so Pro rebuilds its cached conditions. Bulk seeding: `wp elementor kit import path/to/kit.zip [--include=content,templates,site-settings] [--overrideConditions=<ids>] [--sourceType=local|remote|library] [--unfilteredFilesUpload=enable]`; the Design System ZIP imports through the panel ([kit import](https://developers.elementor.com/docs/cli/kit-import)). Templates created through `elementor-create-template` follow the same node shape (verify its arguments with `get-ability-info`).

**Minimal worked example** — hero `e-div-block` with image, heading and button (native JSON; through Novamira the `$$type` envelopes around scalars may be omitted):

```json
{
  "id": "hero", "version": "0.0", "elType": "e-div-block", "isInner": false,
  "settings": [], "editor_settings": [], "interactions": [],
  "styles": { "s-hero": { "id": "s-hero", "type": "class", "label": "local",
    "variants": [ { "meta": { "breakpoint": "desktop", "state": null },
      "props": { "padding": { "block-start": 0, "block-end": 48, "inline-start": 16, "inline-end": 16 } } } ] } },

    { "id": "hero-img", "version": "0.0", "elType": "widget", "widgetType": "e-image", "isInner": false,
```

## 7. Page-by-page build checklist

**Site setup, once.**
1. `elementor-check-setup`: Core ≥ 4.3.4 and Pro on the matching 4.3.x (4.3.3–4.3.5 fixed MCP style loss, settings loss on MCP updates and an Internal-Embedding editing failure), `atomic.runtime_available` true (else WP Admin → Elementor → Editor → Settings → Atomic Editor → "Activate the new experience"; on 4.2.x Settings → Features → Atomic Widgets + Editor V4), CSS Print Method External then Tools → Regenerate CSS & Data ([settings.php](https://raw.githubusercontent.com/elementor/elementor/main/includes/settings/settings.php)), Flexbox Container on, Inline Font Icons on, FA4 off, Optimized Markup on, Optimized Image Loading on, Lazy Load Background Images left on (hero is an `<img>`), Element Cache off on dynamic sites.
2. Import `agency-base-design-system.zip`; set Defaults (h1–h6, p, a, button, div padding 0); rename tokens to the client's semantic names; create the v3 kit globals that Pro widgets need.
3. Fonts per §1: subset, upload, swap filter, Google Fonts Load = Swap, Google Fonts = Disable, Disable Default Fonts/Colors, Regenerate CSS. Hello/Inglelandi theme settings: theme header/footer off, page title off ([Hello settings](https://elementor.com/help/edit-the-hello-theme-settings/)).
4. Child theme: `add_image_size` registrations + `image_size_names_choose`, `site.css` for non-Elementor markup, Polylang conditions mu-plugin, AVIF quality filter.
5. Cache plugin: image lazy-load OFF, Elementor CSS excluded from async/RUCSS, Elementor + jQuery deferred not delayed, Delay-JS for third parties only, one GTM container, CMP excluded from delay.
6. Register the hero/mobile image sizes before uploading media so sub-sizes exist.

**Per page, in order** (home, one inner page, booking/checkout, then the rest):
1. Section spec from the design: list visual bands, map each to §2, mark the LCP candidate (h1 text or hero `<img>`).
2. Export and upload the page's images per §4 (hero ≤ 100 KB mobile variant first).
3. Generate the tree; lint (first section: no `interactions`, no `_animation`; depth ≤ 4; whitelisted widgets; every `e-image` sized; no `<script>` in `html`; no Swiper consumer, Counter, Lottie, Google Maps or Form above the fold; global classes referenced, no local colour/font).
4. `elementor-set-content` to a draft, `elementor-clear-document-cache`, read back ids.
5. Screenshot at 390 px (and 1024/1440/1920 for parity with the design, per the kallyas method); compare with the design frame; fix.
6. Lighthouse 13 mobile, three serial runs, median, `benchmarkIndex` recorded and runs below ~1,000 discarded. Read the insight audits (`lcp-discovery-insight`, `lcp-phases-insight`, `render-blocking-insight`, `dom-size-insight`, `font-display-insight`, `third-parties-insight`, `image-delivery-insight`) ([Lighthouse 13](https://developer.chrome.com/blog/lighthouse-13-0)).
7. **Gate** — all must hold or the page is not published and page N+1 does not start (a documented, owner-accepted exception is the only bypass): median score ≥ 95; LCP ≤ 2.0 s; CLS ≤ 0.05; TBT < 300 ms; ≤ 1 MB; ≤ 50 requests; render-blocking items 0; LCP element text or `<img>` with `fetchpriority=high`, `srcset`, width/height, no `loading=lazy`; LCP render delay < 40% of LCP; third-party ≤ 150 KB / ≤ 300 ms; font files ≤ 4 and all woff2 same-origin; icon-font files 0; `elementor-invisible` count 0 above 800 px at 390 px width; hero media ≤ 100 KB; no Media resource > 500 KB; DOM < 1,500 nodes (target < 800), HTML < 300 KB; `post-N.css` documents ≤ 4 on brochure pages.
8. Publish; purge cache; re-run once on the public URL with a mobile Chrome UA (detect WAF/challenge pages).

**Handover.**
1. Finish all pages, templates and popups, then Elementor → Editor → Home → System → Element Manager → Scan Element Usage → review the third-party filter → Deactivate Unused Elements (elements used only in a popup, template or draft are reported unused and will break — check them first); record the kept list ([Element Manager](https://elementor.com/help/element-manager/)).
2. Run the `elementor-audit` skill on every key page and fix each flag; save each page's Lighthouse JSON (five metric values + DOM count) under the plugin's run folder.
3. Run `references/breakage-checklist.md`: home in each language, one page per layout type, product, empty and filled cart, checkout, my account, 404, popups, mobile menu open, sticky header, forms submit, reCAPTCHA on focus, Polylang switcher — screenshot diff before/after the last global change.
4. Export the final Design System ZIP (client blueprint) and the kit (`--include=site-settings,templates`).
5. The client gets: the Lighthouse medians per page with the PSI link, the token sheet, the Design System ZIP, the kept-elements list, the image-size table, the "do not" list (no new fonts, no add-on packs, no autoplay hero, no page-load popups, one GTM container), and the note that field (CrUX) confirmation follows after 28 days.
