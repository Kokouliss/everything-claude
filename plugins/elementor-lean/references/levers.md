# Levers: taking an Elementor 4.x site to 95–100 on mobile

The ordered playbook for an existing site. Built from adversarially reviewed research (15 dimensions,
303 findings, October 2026; the corpus with every claim's verdict and sources is `data/levers-research.json`)
and from the measurements in `sites-in-the-wild.md`. Sections 1–6: the score, per-site triage, server-side
and caching levers, the cache-plugin matrix, WooCommerce/bookings/multilingual, WordPress 7.x and PHP 8.4.
Sections 7–9: the front-end levers, the never-auto-enable list, the evidence table.

Tags: **auto** = setting or attribute only, reversible, no visible change; **visual check** = markup or
look changes — run `breakage-checklist.md`; **owner OK** = removes approved design, tracking data or legal
behaviour. "(medium)", "(low)", "verify" and "(unreviewed)" mark claims that are not fully confirmed.
Measure before and after every lever; one lever at a time.

## 1. How the score works and what to attack first

Mobile Performance = `round2(Σ metric_score × weight / 100)` over five metrics; INP has weight 0, nothing else is scored. Unchanged from Lighthouse 10 through 13.5.0; PSI moved to 13.x the week of 10 Oct 2025 with "no changes to the performance scoring" ([scoring](https://developer.chrome.com/docs/lighthouse/performance/performance-scoring), [default-config.js](https://github.com/GoogleChrome/lighthouse/blob/main/core/config/default-config.js), [LH 13 blog](https://developer.chrome.com/blog/lighthouse-13-0)).

Each metric score is a log-normal curve through two control points (p10 → 0.9, median → 0.5); value ≤ 0 scores 1.0:

```
x     = ln(value / median) * 0.9061938024368232 / -ln(p10 / median)
score = (1 - erf(x)) / 2          # erf = Abramowitz-Stegun 7.1.26
```

| Metric | Weight | p10 (0.9) | median (0.5) | Avg points lost, 10 agency home pages |
|---|---|---|---|---|
| LCP | 25 | 2500 ms | 4000 ms | 16.2 |
| TBT | 30 | 200 ms | 600 ms | 11.1 |
| CLS | 25 | 0.10 | 0.25 | 0.3 |
| SI | 10 | 3387 ms | 5800 ms | 6.9 |
| FCP | 10 | 1800 ms | 3000 ms | 5.0 |

Desktop has its own curves (LCP 1200/2400, FCP 934/1600, SI 1311/2300, TBT 150/350; RTT 40 ms, CPU ×1) and scores 20–30 points higher on the same page: always `--form-factor=mobile` / `strategy=mobile`.

| Displayed | What it takes (mobile, exact curves) |
|---|---|
| 90 | every metric exactly at p10 (FCP 1.8 s, SI 3.4 s, LCP 2.5 s, TBT 200 ms, CLS 0.10) |
| 96 | CLS 0 + TBT 0 (locks 55 points) with LCP 2.5 s, FCP 1.8 s, SI 3.4 s |
| 99 | CLS 0, TBT 0, LCP 2.0 s, FCP 1.5 s, SI 2.5 s — or CLS 0, TBT 100 ms, LCP 1.8 s, FCP 1.2 s, SI 2.2 s |
| 100 | mean ≥ 0.995: CLS 0, TBT 0, LCP ≤ ~1.5 s, FCP ≤ ~1.2 s, SI ≤ ~2.0 s (TBT 50 ms still allows 100 with LCP 1.3 / FCP 1.0 / SI 1.7) |

Acceptance is per metric: CLS ≤ 0.02, TBT ≤ 100 ms, LCP ≤ 1.8 s, FCP ≤ 1.2 s, SI ≤ 2.2 s (→ ≥ 99). Debloater inventory targets: LCP ≤ 1.55 s, TBT ≤ 65 ms, CLS ≤ 0.04, FCP ≤ 1.1 s, SI ≤ 2.0 s. Print "points lost = weight × (1 − score)" per metric on every run.

**Measurement facts (corrected):**

- **PSI is not the CLI.** CLI default: `simulate`, RTT 150 ms, 1.6 Mbps, CPU ×4, maxWaitForLoad 45 s. PSI mobile runs [lr-mobile-config.js](https://raw.githubusercontent.com/GoogleChrome/lighthouse/main/core/config/lr-mobile-config.js): **cpuSlowdownMultiplier 1.2**, maxWaitForFcp 15 s, maxWaitForLoad 35 s, `modern-http-insight` and `bf-cache` skipped (since Dec 2024, [release notes](https://developers.google.com/speed/docs/insights/release_notes)). A local 4× run over-reports TBT/SI.
- **Calibrate from benchmarkIndex** ([calculator](https://lighthouse-cpu-throttling-calculator.vercel.app/)): m = 3 + (bi−1300)/233 for bi ≥ 1300; 2 + (bi−800)/500 for 800–1299; 1 + (bi−150)/650 for 150–799; < 150 the host is too slow. PSI's 1.2 ≈ bi 280. Probe quietly, pass `--throttling.cpuSlowdownMultiplier=$m`, store bi and m per row. The CLI's slow-host warning fires only at bi ≤ 1000, `channel=cli`.
- **Verdict routing:** LCP/FCP/SI/CLS from the local median; TBT from PSI, or locally only when bi is within ±15 % of PSI's (calibrated local TBT should sit within ~30 %).
- **Runs:** rules.md baseline is 3 serial runs, median + range, bi recorded, runs below ~1000 discarded. To accept or reject one lever use 5 ("median of 5 is twice as stable as 1"), ≥ 2 dedicated cores, never parallel ([lighthouse-ci](https://raw.githubusercontent.com/GoogleChrome/lighthouse-ci/main/docs/configuration.md)). Spread > 6 points: repeat or use PSI. Drop runs with non-empty `runWarnings` (limnoupolis: 45 s timeout, TBT 142,018 ms); if ≥ 3 of 5 warn, report "page never idles" — do not raise `--max-wait-for-load`.
- **Redirects:** PSI resolves 3XX first, the CLI does not (pallada `/`→`/en/` cost 1.1 s). Audit `curl -sIL -o /dev/null -w '%{url_effective}'` and each language home; require `.runWarnings == []`, `.finalDisplayedUrl == requested`.
- **Lighthouse 13 ids.** Legacy audits are gone from the JSON. Shipped ids that differ from the 13.0 blog: **`lcp-breakdown-insight`** (not lcp-phases-insight), **`inp-breakdown-insight`**, **`cache-insight`**. Others as announced: `document-latency-insight` (redirects, server-response-time, uses-text-compression), `lcp-discovery-insight`, `render-blocking-insight`, `third-parties-insight`, `image-delivery-insight`, `font-display-insight`, `cls-culprits-insight`, `dom-size-insight`, `network-dependency-tree-insight`. Every insight id already exists in 12.8.2, so one `triage.jq` reads both; read LCP phases from `lcp-breakdown-insight` even on 12.x (the legacy table yields negative render delay for text LCP). Run `npx -y lighthouse@13` (Node ≥ 22.19), record `.lighthouseVersion`. `third-parties-insight` has no blockingTime — join `bootup-time` with `network-requests[].entity`.
- **PSI API** ([runpagespeed](https://developers.google.com/speed/docs/insights/rest/v5/pagespeedapi/runpagespeed), [get-started](https://developers.google.com/speed/docs/insights/v5/get-started)): `GET …/v5/runPagespeed?url=&strategy=mobile&category=performance&key=`. Default strategy is desktop; keyless calls hit the shared quota (429). Keyed: 25,000/day per GCP project, ~240/min, no rate-limit headers (medium) — ≤ 1/s, back off on 429. Assert `cpuSlowdownMultiplier == 1.2`; call from one fixed server.
- **Field:** ranking uses CrUX p75 (LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1), not the lab score; INP has no lab value ([CWV](https://developers.google.com/search/docs/appearance/core-web-vitals)). PSI's `loadingExperience` is announced for removal — build the Field column on the [CrUX API](https://developer.chrome.com/docs/crux/api) (`POST records:queryRecord`, 150/min) and [History API](https://developer.chrome.com/docs/crux/history-api). Low-traffic villa sites return 404 NOT_FOUND (no data, not auth); then only a RUM beacon proves field success.
- The chrome-devtools MCP `lighthouse_audit` tool excludes performance and defaults to desktop; `performance_start_trace` is for qualitative LCP/CLS culprits only.

**Attack order:** by points lost on the tested page; default LCP → TBT → SI/FCP → CLS as guard. Flip when TBT > 600 ms (score 0, −30): LCP alone cannot pass ~70. CLS is ~0 on 8 of 10 sites and the cheapest to lose: LiteSpeed lazy-load took staging 0 → 0.107 (−3 points, field "Poor").

## 2. Per-site triage

**Inputs:** `audit.php` JSON (`plugins.by_role`, `elementor.features`, `elementor.settings`, `usage.flags`, `kit_fonts`, `db`) + median of 3 `triage.jq` lines on the **final** URL of home, one inner page and the booking/checkout page.

**Gates (before any change or measurement):** (G0) one owner per job — two entries in `plugins.by_role.cache`, or an optimizer beside the cache plugin's own keys (LiteSpeed `optm-js_defer`/`optm-css_min`/`media-lazy`, FlyingPress-CF `FLYING_PRESS_CONFIG`, W3TC Minify) → disable duplicates, owner OK; cache first, delay-all/RUCSS last. (G1) `wp litespeed-option set guest false`, `guest_optm false` before measuring; final URL; bi recorded. (G2) V4: experiment `e_opt_in_v4`/`e_atomic_elements` active or widgetType `e-*` in `_elementor_data` → RUCSS/UCSS opt-in, Perfmatters ≥ 2.6.9 only ([changelog](https://perfmatters.io/docs/changelog/), [Elementor 4.0](https://developers.elementor.com/elementor-editor-4-0-developers-update/)); enumerate live `elementor_experiment-*` options, no hard-coded list. (G3) exclusion lists from section 5 exist when `plugins.by_role` has woocommerce/booking/filters.

**Lever order** (one setting, one measurement, keep/undo, before-value stored): L1 cache/TTFB → L2 LCP-element class → L3 third parties → L4/L5 fonts, icons, render-blocking CSS, first-screen animations → L6 RUCSS → L7 delay-all. Owner OK at G0, L2 banner/hero brief, L3 gating, L6, L7.

**Classify the LCP node first** from `lcp-breakdown-insight`: `img`, `text`, `consent-banner-text` (selector matches `/cmplz|faz-notice|cookie|consent|cky-|moove|gdpr|cookie-script/i`), `video/canvas/background`. On 3 of 9 sites the LCP is the consent banner (pallada, cretaforums: FAZ `div.faz-notice … p`; onar: `#cmplz-message-2-optin`, LCP 16.4 s) — hero levers cannot move it. Text LCPs lose mostly in `elementRenderDelay` (voreniahorizon h1 2693 ms, 160 entrance animations).

|---|---|---|---|
| `ttfb_fast == false` or no cache footprint (`x-litespeed-cache: hit`, `cached by FlyingPress`, `by W3 Total Cache`) | L1 page cache + crawler/preload | server time 1.7–13 s → < 0.6 s; up to 25 points on cache-less sites | auto |

**Stopping rules.** After each lever print a residual per metric: value, target, culprit (`lcp_type`+selector+dominant phase; `bootup_by_entity`; `render_blocking_top`; `cls-culprits-insight`), next lever. Stop when two consecutive levers improve the target by < 5 %; escalate "DESIGN CHANGE REQUIRED" when the LCP is canvas/video, the chain contains three.js/.glb, first-party bootup stays > ~2 s after defer (use `bootup-time.numericValue`, scripting + parse, not per-URL `total`), or third-party main thread stays > 250 ms because gating is refused.

**Googlebot guard.** Google Search does not interact with the page, so delayed-until-interaction scripts never run for it. Default to "delay specified scripts"; exclude Elementor frontend/webpack/hooks/i18n, JetSmartFilters, loop/load-more, reviews, forum JS; FlyingPress-CF `js_lazy_render` off on content pages; verify rendered HTML in URL Inspection.

## 3. Server-side and caching levers

### Page cache — **auto**
*Worth:* the only way to pass the 600 ms server-response check (`document-latency-insight`, `TOO_SLOW_THRESHOLD_MS = 600`, [DocumentLatency.ts](https://raw.githubusercontent.com/ChromeDevTools/devtools-frontend/main/front_end/models/trace/insights/DocumentLatency.ts)): a HIT returns HTML in 0.15–0.6 s, PHP renders cost 1.7–13 s here. "Cache plugin installed" is no lever (rules.md 17) — a missing or bypassed cache is the finding.
*How:* LiteSpeed Cache > Cache: Enable Cache ON, Cache Mobile OFF, Cache Login Page OFF; TTL 604800 (36000–86400 where cached HTML embeds nonces); Do Not Cache Cookies **empty**; Purge > Serve Stale ON; Crawler ON, Server Load Limit = cores/2, sitemap index ([cache](https://docs.litespeedtech.com/lscache/lscwp/cache/), [general](https://docs.litespeedtech.com/lscache/lscwp/general/)). Use LiteSpeed Cache on LiteSpeed servers instead of W3TC/WP Rocket. FlyingPress: Caching > Cache Lifespan, Preload after purge. W3TC: Page Cache Disk: Enhanced, Minify and Lazy Load OFF. Plesk: untick "Enable nginx caching" when a WordPress cache exists (cretaforums: `x-cache-status: MISS` over a FlyingPress HIT; purges never reach nginx; medium, [Plesk](https://docs.plesk.com/en-US/obsidian/administrator-guide/web-servers/apache-and-nginx-web-servers-linux/nginx-caching.74849/)).
*Breaks when → fix:* consent/analytics cookie in Do Not Cache Cookies → remove; Guest Mode ON (first-visit swap, wrong language/prices) → OFF, never auto-enable; WP-Cron needs PHP hits → system cron `*/15 * * * * curl -sS -o /dev/null https://domain/wp-cron.php?doing_wp_cron` + `DISABLE_WP_CRON` ([troubleshoot](https://docs.litespeedtech.com/lscache/lscwp/troubleshoot/)); Set-Cookie on every response (Polylang `pll_language`, server-side Meta `_fbp`) fragments the cache → fix at the plugin or LiteSpeed Cache > Vary > Vary Cookies.
*Verify:* second `curl -sI -A '<mobile UA>'` shows the footprint; `ttfb_fast == true`; Crawler Summary "completed".

### Object cache — **auto** (server-side, not a score lever)
Nothing for cached pages; main lever for uncached paths (cart 3.1 s, my-account 2.7 s, `wc-ajax` 1.7 s, logged-in forum) (medium). Redis: LiteSpeed Cache > Cache > Object: ON, Method Redis, Default Object Lifetime 360, Persistent Connection ON, unique Redis Database ID per site; W3TC Redis on VPS only; FlyingPress 5.6+/WP Rocket via the host drop-in, one `object-cache.php` ([FlyingPress Redis](https://docs.flyingpress.com/en/articles/15588084-redis-object-caching)). *Breaks when → fix:* Memcached vs multi-MB `_elementor_data` (LiteSpeed's "Do Not Cache Groups posts/post_meta" is a Memcached+SASL workaround only); 2026 reports of a broken Elementor editor/Global Settings and WPML switcher fixed by LiteSpeed object cache OFF (medium) → Redis, then test a save and a Global Color change. *Verify:* "Connected"; `curl -w '%{time_starttransfer}'` on `/cart/`.

### TTFB and hosting — **auto**; redirects **owner OK**
Origins: agency Plesk servers, Hetzner LiteSpeed (HTTP/3, Brotli) and LeaseWeb nginx (no HTTP/3). Keep Hetzner LiteSpeed as origin; nginx sites get a page cache and UDP 443 or Cloudflare. Remove PHP language redirects at `/` (Polylang: Detect browser language OFF, "Hide URL language information for default language" ON; WPML: "Don't redirect") — pallada's 302 costs 0.65–1.2 s `no-store` for every visitor ([WP Rocket 76](https://docs.wp-rocket.me/article/76-translation-multilingual-plugins)); if required, redirect client-side or at the edge. Compress `.glb` (`model/gltf-binary`). Elementor Element Caching (24 h) shortens uncached renders only, is experimental and must be Inactive on widgets with dynamic tags, shortcodes, cart, booking or user data — drop the `element_cache_on` auto-action ([Elementor help](https://elementor.com/help/element-caching-help/)). *Breaks when:* a Greek shared plan replaces Hetzner (Cloudflare already terminates in Athens/Thessaloniki; PSI measures from a European Google datacenter). *Verify:* `curl -sI https://domain/` → 200 + HIT, no `no-store`, `alt-svc: h3`; redirect count 0.

### CDN / edge — **check** (field gain, modest lab gain)
Four Cloudflare sites serve HTML `cf-cache-status: DYNAMIC`; edge HTML caching helps Greek field TTFB, lab TTFB marginally (medium) ([APO](https://developers.cloudflare.com/automatic-platform-optimization/about/index.md)). Options: APO + Cloudflare plugin, FlyingPress ≥ 5.1 full-page cache, QUIC.cloud on LiteSpeed. **Rocket Loader OFF everywhere** (breaks the Elementor editor and the Bookings calendar); APO never with LiteSpeed Guest Mode/ESI; Speed Brain OFF while HTML is DYNAMIC (prefetches 503 and eat Chrome's two speculation slots, [Speed Brain](https://developers.cloudflare.com/speed/optimization/content/speed-brain/)). *Breaks when:* "Cache Everything" without cookie bypass; LiteSpeed purge not reaching APO; WooCommerce "Geolocate (with page caching support)" appends `?v=<hash>` → "Shop base address" ([Woo geolocation](https://developer.woocommerce.com/2015/07/02/making-geolocation-static-cache-friendly-in-2-4/)). *Verify:* `cf-cache-status: HIT`, `cf-apo-via: tcache`; `/cdn-cgi/trace` `colo=ATH|SKG`.

### Database bloat — revisions **owner OK**
Low worth once cached. Measurable: autoloaded options (Site Health > 800,000 bytes), never-expiring transients, Elementor revisions (slow saves/backups only). `WP_POST_REVISIONS 10`; `wp transient delete --expired`; `SELECT option_name, LENGTH(option_value) FROM wp_options WHERE autoload IN ('yes','on','auto-on') ORDER BY 2 DESC`; prune revisions last, on a verified backup ([set_transient](https://developer.wordpress.org/reference/functions/set_transient/)). *Breaks when:* booking/filter transients deleted; `autoload=off` on a per-request option. *Verify:* Site Health no longer flags autoloaded options.

### PHP — **auto** (uncached paths only)
`WP_MEMORY_LIMIT` 512M ([requirements](https://elementor.com/help/requirements/)); OPcache `memory_consumption=256`, `interned_strings_buffer=32`, `max_accelerated_files=20000`, `validate_timestamps=1`; JIT default (off). Production `WP_DEBUG false`, `WP_DEBUG_DISPLAY false`; preflight `display_errors`, `debug.log` size (> 50 MB stop). *Breaks when:* `validate_timestamps=0` with auto-updates. *Verify:* Site Health Info > Server; OPcache hit rate > 95 %; HTML starts with `<!DOCTYPE`.

### 7.6 Animations and motion

**Mechanism and worth.** `element-base.php` adds `elementor-invisible` (`visibility:hidden`) to any element with an entrance animation; `global.js` removes it on viewport entry, so the LCP element paints only after Elementor JS runs, never before interaction if that JS is delayed. Bytes are trivial (0.4-0.6 KB CSS per animation); time is not: voreniahorizon's `h1` with `_animation: fadeIn` has Render Delay 7,831 ms of an 8.95 s LCP; cretaforums 3,620 ms; pallada keeps 90 animations but an un-animated LCP paragraph (Render Delay −344 ms) ([3.32 update](https://developers.elementor.com/elementor-3-32-developers-update/)). ## 8. Never auto-enable

Report, then wait for a human.

- **CSS Print Method = Internal Embedding** — #37468 breaks REST/admin-ajax saves; conflicts with caching.
- **Element Cache on, or TTL change** — stale/other-language HTML, dead form nonces; no score evidence; purges all CSS.
- **Optimized Markup on an existing site** — wrapper CSS and add-ons break; DOM did not move scores.
- **Atomic Editor / `e_atomic_elements` / `e_opt_in_v4` on production** — mixed v3/v4 style loss, option bloat.
- **Deactivating `container`, `nested-elements` or hidden experiments** — blank front end.
- **`e_optimized_css_files`** — alpha; may skip a needed purge; not a size lever.
- **Load Font Awesome 4 Support = No** before an empty `fa fa-` grep — icons vanish.
- **Google Fonts = Disable** before the widget-override audit — stray families fall to system fonts.
- **LiteSpeed 'Remove Google Fonts' / 'Load Google Fonts Asynchronously'** — strips fonts or adds FOUT.
- **Subsetting a commercial font; changing a family** — EULA; design.
- **Delay-all JS, or delaying Elementor frontend, jQuery, the CMP or the consent-default snippet** — blank animated elements, late banner, tags without consent.
- **Basic consent mode, consent-gated tags, Meta autoConfig off, deleting inline gtag/fbq, removing WooCommerce GA or a CMP** — lost modelling, auto events, ecommerce, conversions; GTM wiring and legal.
- **Perfmatters Local Analytics Minimal; server-side GTM** — no events/Ads; infrastructure and consent forwarding.
- **Removing a hero video, slider, Lottie, 3D canvas, Animated Headline or animations; 'Play On Mobile' = No; click-to-play YouTube** — approved design.
- **Device-vary caching or `wp_is_mobile()` rules** — doubles cache and CCSS quota per language; wrong variant cached if a layer is missed.
- **Optimized Image Loading = Disable without a fetchpriority rule** — hero at Low priority everywhere.
- **Lazy Load Background Images = Disable globally** — use `e-no-lazyload` instead.
- **LiteSpeed Lazy Load Images ON without Responsive Placeholder + Add Missing Sizes** — CLS 0 to 0.107.
- **Adding, removing or switching an image converter** — rewrite rules, `Vary: Accept`, `<picture>` conflicts.
- **Global Image Lightbox off; Element Manager deactivation; site-wide Script Manager disables; dropping an add-on or icon plugin** — galleries open as raw files; blank areas in templates, popups, loop items; booking dependencies.
- **Disabling cart fragments on shop/product/cart pages** — mini-cart stops updating.
- **Trashing templates/popups without conditions; narrowing popup conditions; Elementor Canvas on checkout** — translations and Template-widget references; openers silently fail; navigation, banner and footer GTM vanish.
- **Removing reCAPTCHA / Honeypot swap** — spam policy.
- **Theme switch** — not a lever; drops template parts and Polylang strings.
- **Core/Pro updates; Replace URL + Clear Files & Data on live** — same-minor pairing on staging; font re-download needs writable uploads.
- **RUCSS/UCSS or Delay-JS in the cache plugin** — interaction-only selectors and handlers (part A §4); safelist and click-through first.
